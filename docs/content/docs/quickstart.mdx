By the end of this page you have one `attach()` call in your agent and a cost row on screen for a real call.

You need Python 3.11 or later and API keys for one STT, one LLM and one TTS provider. On LiveKit you also need a project: a free LiveKit Cloud project or a local `livekit-server --dev` both work.

<Steps>
<Step>

### Install

VoiceGateway bundles no provider plugins. It meters the ones you already construct, so install those next to it.

<Tabs items={['LiveKit', 'Pipecat']}>
<Tab value="LiveKit">

```bash
pip install "voicegateway[livekit,dashboard]"
pip install "livekit-agents[silero]"
pip install livekit-plugins-openai livekit-plugins-deepgram livekit-plugins-cartesia
```

</Tab>
<Tab value="Pipecat">

```bash
pip install "voicegateway[pipecat,livekit,dashboard]"
pip install "pipecat-ai[openai,deepgram,cartesia,daily]"
```

The `livekit` extra is there on purpose: the `voicegw` CLI loads its LiveKit diagnostics at startup. Your agent still imports no LiveKit code.

</Tab>
</Tabs>

`dashboard` adds the web server that `voicegw serve` runs in step 3.

</Step>
<Step>

### Add attach() to your agent

One call, before the session or pipeline starts. Your providers stay exactly as they are.

<Tabs items={['LiveKit', 'Pipecat']}>
<Tab value="LiveKit">

```python title="agent.py"
from livekit.agents import Agent, AgentSession, WorkerOptions, cli
from livekit.plugins import cartesia, deepgram, openai

import voicegateway


async def entrypoint(ctx):
    await ctx.connect()
    session = AgentSession(
        stt=deepgram.STT(model="nova-3"),
        llm=openai.LLM(model="gpt-4o-mini"),
        tts=cartesia.TTS(model="sonic-3"),
    )
    voicegateway.attach(session, project="my-agent")
    await session.start(agent=Agent(instructions="Be helpful."), room=ctx.room)


if __name__ == "__main__":
    cli.run_app(WorkerOptions(entrypoint_fnc=entrypoint))
```

Set `LIVEKIT_URL`, `LIVEKIT_API_KEY` and `LIVEKIT_API_SECRET`, plus the provider keys (`DEEPGRAM_API_KEY`, `OPENAI_API_KEY`, `CARTESIA_API_KEY`). The worker checks the LiveKit ones before it runs your code.

</Tab>
<Tab value="Pipecat">

```python title="agent.py"
task = PipelineTask(
    pipeline,
    params=PipelineParams(enable_metrics=True, enable_usage_metrics=True),
)
voicegateway.attach(task, project="my-agent")
await PipelineRunner().run(task)
```

Both `enable_metrics` and `enable_usage_metrics` are required. Without them Pipecat emits no usage frames, and the dashboard stays empty with no error to say why.

</Tab>
</Tabs>

</Step>
<Step>

### Start the dashboard

In a second terminal:

```bash
voicegw init    # writes voicegw.yaml, which the server needs
voicegw serve   # API and dashboard on http://localhost:8080
```

`attach()` needs no config file. It writes to `~/.config/voicegateway/voicegw.db`, and the config `voicegw init` writes reads from the same file. That is the whole wiring.

</Step>
<Step>

### Place a call and read the cost

Run the agent (`python agent.py dev` on LiveKit) and talk to it. On LiveKit, the [Playground](https://playground.livekit.io) gives you a microphone. End the call, then open the Costs page at `http://localhost:8080`.

From the terminal:

```bash
voicegw logs    # one row per request: modality, model, cost, latency
voicegw costs   # totals per provider and project
```

</Step>
</Steps>

## Nothing showed up

| Symptom | Cause |
|---|---|
| LiveKit worker exits with a `ValueError` at startup | `LIVEKIT_URL`, `LIVEKIT_API_KEY` or `LIVEKIT_API_SECRET` is unset |
| Pipecat call connects, dashboard stays empty | `enable_metrics` or `enable_usage_metrics` is off |
| `ConfigError: No voicegw.yaml found` | Run `voicegw init` first |
| The browser cannot connect | Nothing is serving. `voicegw dashboard` opens the URL; `voicegw serve` starts the server |
| Rows show zero cost | A self-hosted model (`local/*`, `ollama/*`). Those price at zero by design |
